# 邀请认领 MVP（Issue #7）

- Prisma schema 是数据模型来源；本次 migration 仅增加邀请有效期、口令哈希，不需要在线数据库。
- 运行时写入 `data/mail/mail.json`（可用 `MAIL_DATA_DIR` 指定目录），与 letter-kit 的 `data/letters` 分离。一个快照内保存 users、invitations、letters、relationships，临时文件写入后原子重命名；进程内串行更新，保证一次认领同时更新三种记录。仅适用于单 Node 进程、持久化磁盘的 MVP；多实例部署应切换数据库事务。
- 邀请默认 7 天，支持 1–30 天，token 为 32 字节随机数。口令以随机盐 + scrypt 哈希保存，不保存明文。预览验证凭据是 token 路径下的短期 HttpOnly cookie；认领操作仍重新验证输入口令和邀请状态，不依赖预览凭据。
- 接收后直接将信记为 `DELIVERED`，在仅收件人可访问的 `/app/letters/[id]` 阅读，双方进入通信簿。真实邮路和配送延迟留给后续阶段。
- 拒收将邀请记为 `REJECTED`，关系记为 `BLOCKED`，不分配信件收件人；新邀请不能覆盖已有屏蔽关系。已认领、拒收、过期邀请不再显示内容或允许认领。
- cookie 会话继续沿用内测登录机制，不是正式身份认证。登记时分配稳定内部 ID 和唯一公开邮寄号；同一会话再次登录沿用 ID，退出后重新登记会建立新身份，昵称不用于账号查找。旧 cookie 可经登录入口补齐内部 ID。
- `/app/contacts` 只显示已通邮联系人及公开邮寄号，不提供搜人或按 ID 寄信功能；后者属于 #8。

手工验收：浏览器 A 登录 → 写给新人（可设口令）→ 复制链接 → 浏览器 B 打开 → 错误口令不显示正文 → 正确口令查看 → 登记并认领 → 获得邮寄号和信件详情 → A/B 通信簿互见 → 再开邀请提示已认领。另建邀请测试「拒收并屏蔽」。
