# 收件人关系与后续寄信流程

## 核心结论（Neil 已确认）

每人有一个**独一无二的公开用户 ID**。熟人间用 ID 发信、收信；给还没注册的人写信时，不要求对方先有 ID，而是靠**一次性邀请链接认领**建立关系。

也就是说：

> 第一封信（对新用户）靠邀请链接认领并分配/沿用 ID；之后靠公开 ID 与通信簿持续通信。不做广场搜人。

## 用户 ID

- 注册后系统分配唯一公开 ID（短码）；可选支持用户自定义唯一短码。
- 已知对方 ID：写信时填 ID，或从通信簿选择。
- 不知道对方 ID、对方也未注册：走邀请链接，不要求预先提供 ID。
- 不提供邮箱/手机号搜人、不提供广场发现入口。

## 首次邀请流程（收信冷启动）

1. A 注册并获得自己的公开 ID。
2. A 写一封信，填写对方称呼（例如「小林」），可选大致收信地。
3. 系统生成**一次性**邀请收信链接（可设过期时间、可选口令）。
4. A 把链接通过微信/QQ/短信等发给 B。
5. B 打开链接：可先看到「有人给你写了一封信」再注册/登录。
6. B 认领这封信，设置昵称、常驻城市/收信邮局；系统为其分配公开 ID（或沿用已有账号的 ID）。
7. 认领时可设对 A 的昵称备注；可选：允许后续来信 / 拒收并屏蔽。
8. 系统把 A 与 B 建立为通信关系，双方进入彼此通信簿。
9. 信件进入正常配送/送达/打开流程。

## 后续寄信流程

当 B 已注册并认领过第一封信后，A 再写信时：

1. A 进入写信页面。
2. A 从通信簿选择 B，或直接填写 B 的公开 ID。
3. 系统读取 B 当前默认收信城市/邮局。
4. A 到自己所在地邮局寄出。
5. 信件按双方邮局计算距离与送达时间。
6. B 送达后打开。

此时不再需要邀请链接。

## 联系人关系怎么生成

推荐「通信关系」而不是传统好友关系。

### pending_invite

A 写了信并生成邀请链接，B 尚未注册/认领。

### connected

B 已注册并认领，双方可用 ID 互寄。

### blocked

一方拉黑另一方，不能继续寄信。

### archived

关系归档，不显示在默认通信簿，历史信件仍可保留。

## 是否需要双方同意？

第一封信被 B 主动认领，即同意建立通信关系。

认领时 B 应看到：谁邀请了你、对方给你的备注/称呼、是否允许对方以后继续来信。

B 可以选择：

1. 接收这封信，并允许后续来信。
2. 只接收这封信，不建立通信关系。（第二阶段）
3. 拒收并屏蔽邀请人。

MVP 先做选项 1 和 3。

## 收信地址如何更新

B 注册后设置默认收信位置：常驻城市、默认邮局。后续寄信使用 B 当前默认位置。已在路上的信按寄出时锁定的地址配送，不重新改道。

## 产品体验上的表达

推荐「通信簿」。写信入口：

- 写给通信簿里的人（或填对方公开 ID）
- 写给一个新的人（生成邀请链接）
- 写给未来的自己（后续）

漂流瓶等陌生人玩法**不纳入**当前已确认路线。

## MVP 推荐方案

1. 注册即得公开用户 ID。
2. 寄给新人：生成一次性邀请链接（可过期/可口令）。
3. 对方经链接注册/登录并认领 → 得 ID、进通信簿。
4. 之后用 ID / 通信簿互寄。
5. 每次寄信锁定双方当时的邮局位置。
